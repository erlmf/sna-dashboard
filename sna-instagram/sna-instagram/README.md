## ⚙️ Architecture Decisions & Reasoning

### Why PostgreSQL?
- Relational model fits perfectly: users ↔ edges ↔ communities
- JSON column support → store flexible whitespace analysis results
- `asyncpg` driver → non-blocking I/O in FastAPI (handles concurrent dashboard requests)
- Industry standard — easy to hand off to production

### Why FastAPI?
- Native async → pairs perfectly with `asyncpg`
- Auto-generated Swagger docs at `/docs`
- Pydantic validation out of the box
- Fast to build, easy to extend

### Why react-force-graph?
- WebGL rendering → handles 500+ node graphs smoothly in browser
- Built-in zoom, pan, drag
- Easy React integration (vs raw D3 which requires manual DOM management)

### Why Louvain for community detection?
- O(n log n) — scalable to large networks
- Optimizes modularity directly (the standard metric for community quality)
- Handles weighted graphs natively
- `python-louvain` library wraps it cleanly for NetworkX graphs

### Why composite influence score instead of single metric?
- **PageRank alone**: misses bridge nodes (high betweenness, low in-degree)
- **Degree alone**: counts bots/spam accounts as influential
- **Composite**: robust across different network structures

## 🚀 Setup & Running

### Prerequisites
- Python 3.10+
- Node.js 20+
- Docker & Docker Compose (for DB)

### Step 1: Data Preparation
```bash
# Copy your dataset to:
cp your_dataset.csv data/raw/dataset.csv
```

### Step 2: Install Notebook Dependencies
```bash
pip install pandas numpy matplotlib seaborn networkx python-louvain pyvis scipy jupyter
```

### Step 3: Run EDA Notebook
```bash
cd notebooks
jupyter notebook 01_EDA.ipynb
# Run all cells
# CHECK THE SUMMARY at the bottom — it tells you the state of your data
# SEND the output to your team lead / Claude for next steps
```

### Step 4: Run SNA Analysis Notebook
```bash
jupyter notebook 02_SNA_Analysis.ipynb
# Run all cells
# Output: data/processed/graph_data.json (the critical file)
```

### Step 5: Start Database
```bash
docker-compose up db -d
```

### Step 6: Load Graph into Database
```bash
cd backend
pip install -r requirements.txt
cp .env.example .env
python -m app.services.graph_loader
```

### Step 7: Start Backend
```bash
uvicorn app.main:app --reload --port 8000
# API docs: http://localhost:8000/docs
```

### Step 8: Start Frontend
```bash
cd frontend
npm install
npm run dev
# Open: http://localhost:5173
```

### Or: Run everything with Docker
```bash
# First run notebooks locally (Docker doesn't have Jupyter set up)
# Then:
docker-compose up --build
```

## ⚠️ Missing Data & What's Needed for Better SNA

The current dataset allows inference of edges from:
1. `@mentions` in content → strongest edges
2. Keyword co-occurrence → secondary edges

**What would significantly improve the SNA:**

| Data | Why Needed | Where to Get |
|------|-----------|--------------|
| Comment data (who commented on whose post) | Direct explicit edges | Instagram Graph API / scraping |
| Follower/following relationships | Ground-truth network topology | Instagram Graph API |
| Reply-to data | Conversation thread edges | API |
| Story mentions | Additional interaction signals | API |
| Post engagement by user (who liked) | Explicit edge weights | API |

**Without explicit comment/follow edges**, the current network is an **inferred approximation** — still valid for community discovery and relative influencer ranking, but not a true interaction graph.

## 📈 SNA Metrics Explanation

| Metric | What It Measures | Use Case |
|--------|-----------------|----------|
| PageRank | Importance based on who points to you | True influence (quality over quantity) |
| Betweenness | Bridge/broker role in network | Information flow control |
| In-Degree | Raw # of incoming connections | Popularity |
| Closeness | Average distance to all nodes | Speed of info spread |
| Eigenvector | Connected to other important nodes | Prestige/quality connections |
| Louvain Modularity | Strength of community structure | 0.3+ good, 0.5+ excellent |
